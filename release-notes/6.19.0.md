## <a name="features"></a>Features

### Core CiviCRM

- **Send preview email from MessageAdminUI
  ([dev/core#6447](https://lab.civicrm.org/dev/core/-/work_items/6447):
  [35648](https://github.com/civicrm/civicrm-core/pull/35648))**

  Support sending yourself a test email from Message Admin.

- **FTS - use `contact_names` index for quicksearch
  ([36085](https://github.com/civicrm/civicrm-core/pull/36085))**

  Uses FTS for contact name quicksearch for more flexible matching and improved
  performance.

- **FTS - add Api4 support
  ([35867](https://github.com/civicrm/civicrm-core/pull/35867))**

  Adds APIv4 support for Mysql Full Text Search

- **Allow EntityReference custom field "Advanced Filter" to accept a raw
  where-clause ([36351](https://github.com/civicrm/civicrm-core/pull/36351))**

  Allows one to use a JSON formatted where-clause filter in the "Advanced
  Filter" for custom fields. The allows for a lot more flexibility and
  possibilities for those fields.

- **Make relationship created & modified dates, description FormBuilder filters
  ([36445](https://github.com/civicrm/civicrm-core/pull/36445))**

  Makes "Relationship created", "Relationship modified date" and "Relationship
  Description" available as formbuilder filters.

- **Api4 - Return itemized errors from Relationship create/save/update
  ([36449](https://github.com/civicrm/civicrm-core/pull/36449))**

  Improves error messaging for the APIv4 Relationship entity.

- **SearchKit - Add a Color field type to the bulk-edit task's input
  ([36513](https://github.com/civicrm/civicrm-core/pull/36513))**

  Adds a native color picker for fields declared as input_type: 'Color',
  everywhere SearchKit renders an editable input for a field value — the generic
  bulk-edit "Update" task and inline in-place cell editing on a table display
  alike, since both go through the same shared input component.

- **SearchKit - Improve smart group UX
  ([36436](https://github.com/civicrm/civicrm-core/pull/36436))**

  Minor tweaks to SmartGroup UX in SearchKit. Specifically: Linking directly to
  group tab from "Edit Smart Group Criteria" button and Removing extra "Display"
  header under "Add Smart Group"

- **SearchKit: Allow joining entity displays on (some) aggregated IDs
  ([36584](https://github.com/civicrm/civicrm-core/pull/36584))**

  Makes it so one can use aggregated foreign keys for joins, provided they only
  return a single value that corresponds to an actual row in the foreign table.

- **Afform - implement BETWEEN/NOT BETWEEN operators for conditional rules
  ([36518](https://github.com/civicrm/civicrm-core/pull/36518))**

  Add more operator options for formbuilder conditional rules.

- **enable adding nav buttons to afTabset for basic paginated form
  ([34495](https://github.com/civicrm/civicrm-core/pull/34495))**

  Adds the ability to add navbuttons to a tabset for basic paginated forms.

- **Afform - Let Form Builder point a dynamic foreign key at another entity on
  the form ([36587](https://github.com/civicrm/civicrm-core/pull/36587))**

  Form Builder can point a foreign key at another entity on the same form —
  that's how contact_id: 'Individual1' is set. It can't do that for a dynamic
  foreign key, so anyone using one has to hand-edit the form markup.

- **Afform - Broadcast afFormPreSubmit event before building the submit request
  ([36506](https://github.com/civicrm/civicrm-core/pull/36506))**

  Adds a new afFormPreSubmit event, broadcast by afForm.component.js immediately
  before it builds the Afform.submit API call. This lets independent Angular
  components (for example a third-party form element like a CAPTCHA widget)
  write a last-moment value into the form's data before it's read for
  submission, without needing to monkey-patch ctrl.submit itself.

  This follows the same broadcast/listen pattern Afform already uses for
  afFormReset and afIfDestroy — a component broadcasts a lifecycle moment and
  unrelated field/element components can listen and react, with no direct
  coupling between them.

- **Localization settings - allow any language for contact default
  ([36588](https://github.com/civicrm/civicrm-core/pull/36588))**

  Default contact language can be the existing automatic options + any of the
  options in languages option group

- **UtilsSql - Optimize inserts with int values
  ([36427](https://github.com/civicrm/civicrm-core/pull/36427))**

  Slightly speeds up inserts by skipping string escaping when it's redundant.

- **Double length of CustomGroup.title schema field
  ([36631](https://github.com/civicrm/civicrm-core/pull/36631))**

  Allows custom group titles to be up to 128 characters long.

  ([35329](https://github.com/civicrm/civicrm-core/pull/35329))**

- **Formbuilder Payments: Add the payment processor ID to a recur
  ([35996](https://github.com/civicrm/civicrm-core/pull/35996))**

  When we submit a form for payment and call startCheckout() we have a
  checkoutOption but not a payment processor. This means that the
  ContributionRecur.payment_processor_id never gets set and none of the
  functions that rely on that work (updating billing details, cancelling recur
  etc).

  ([36285](https://github.com/civicrm/civicrm-core/pull/36285))**

  Supports api4-style custom field tokens in mailings, including pseudoconstants
  like {mailing.mailing_extra_info.priority_level:label} and joins to entity
  reference fields like
  {mailing.mailing_extra_info.assigned_author.display_name}

- **CiviMail - Support custom fields in Mailings
  ([36282](https://github.com/civicrm/civicrm-core/pull/36282))**

  Exposes custom data to the CiviMail UI by using an Afform fieldset per custom
  group.

  ([34794](https://github.com/civicrm/civicrm-core/pull/34794))**

  Ensures when adding cc or bcc addresses using the hook
  hook_civicrm_alterMailParams for a mass mailing, cc and bcc addresses are
  respected.

- **Increase Tag name and label column lengths to 128
  ([36632](https://github.com/civicrm/civicrm-core/pull/36632))**

  Makes it so one can add a tag with a name and/or label up to 128 characters
  long.

- **Extract crmSearchAdminTags into a shared crmEntityTags component
  ([36492](https://github.com/civicrm/civicrm-core/pull/36492),
  [36511](https://github.com/civicrm/civicrm-core/pull/36511),
  [36517](https://github.com/civicrm/civicrm-core/pull/36517) and
  [36502](https://github.com/civicrm/civicrm-core/pull/36502)**

  Consolidates and improves the tags interface for searchkit and afform.
